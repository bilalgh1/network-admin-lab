# Incident 06 — Windows Server installation failure

## Category
Installation / virtualization

## Context

Installing Windows Server 2022 for the `DC-Server1` VM, intended to become the Active Directory domain controller.

## Symptom 1 — immediate installer failure

Right at setup launch, error message:
```
Windows cannot find the Microsoft Software License Terms. Make sure the installation sources are valid and restart the installation.
```

### Diagnosis
Checked the ISO's integrity (consistent size, ~4.69 GB, downloaded from the official Microsoft site) → file not corrupted. Inspected the VM's VirtualBox configuration: found a **Floppy controller with an "Unattended-....iso" file**, automatically generated by VirtualBox 7.x's "New Virtual Machine" wizard via the **"Proceed with Unattended Installation"** option, checked by default.

### Root cause
The auto-generated answer file (`autounattend.xml`) didn't exactly match the Windows Server edition on the ISO, causing this failure right at the start of setup.

### Fix
Deleted the VM, recreated it while explicitly **unchecking "Proceed with Unattended Installation"** at creation time — switched back to a classic manual install (language choice, edition, install type, etc.).

## Symptom 2 — VM frozen during installation

After fixing symptom 1, the install gets stuck at "Getting files ready for installation (17%)" with no visible progress for several minutes, and the host mouse cursor appears unresponsive inside the VM window.

### Paths explored (no single confirmed cause)
- Checked CPU usage of the VirtualBoxVM.exe process on the host
- Checked resources allocated to the VM (RAM, CPU count)
- Checked boot order (Boot Device Order)
- Tried manually selecting the boot device via the F12 menu
- Verified the ISO's SHA256 checksum

None of these paths produced a single, confirmed root cause.

### Resolution
Deleted the VM entirely and recreated it cleanly (rather than continuing to debug a potentially corrupted state). The new install, with the same settings (4096 MB RAM, 2 CPUs, manual install), completed without freezing, all the way to the administrator password setup screen.

## Verification

Successfully logged into the Windows Server desktop, Server Manager opened normally.

## Lesson learned

Two separate takeaways:
1. Check and disable a virtualization tool's "automatic"/"unattended" install features if a manual, fully controlled install is the goal — their default behavior may not be compatible with the exact edition on a given ISO.
2. Facing an installer freeze with no identifiable cause despite several reasonable diagnostic paths, starting from a clean environment (recreated VM) is sometimes more time-efficient than stubbornly debugging an uncertain state — a pragmatic trade-off worth recognizing in a professional setting.
