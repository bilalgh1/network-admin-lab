# Incident 07 — "Destination host unreachable" despite correct IP configuration

## Category
Procedure / basic sanity check

## Context

First connectivity check from `DC-Server1` (Windows Server), right after configuring its static IP (`10.10.20.20/24`).

## Symptom

```
ping 10.10.20.1
ping 10.10.20.10
```
Both commands return immediately, for every packet:
```
Reply from 10.10.20.20: Destination host unreachable.
```
(a reply generated by the local machine itself, not a network timeout)

## Hypotheses tested

1. **Incorrect IP configuration** → checked via `ipconfig /all`: address (`10.10.20.20/24`), subnet mask, gateway (`10.10.20.1`), all correct.
2. **Misconfigured VirtualBox network adapter** → checked by reviewing the VM's Network tab: "Enable Network Adapter" checked, "Internal Network" mode, correct name `intnet-servers`, "Cable Connected" checked.

The two most likely technical hypotheses were ruled out after careful verification.

## Root cause

**`OPNsense-FW` and `SRV-Ubuntu1` — the other machines on the SERVERS network, including the gateway itself — were simply powered off.** No configuration issue at all: the machine literally had no one to talk to on the network.

## Fix

Started `OPNsense-FW` and `SRV-Ubuntu1`.

## Verification

```
ping 10.10.20.1
```
→ 0% loss, immediate success.

## Lesson learned

Before any in-depth network diagnosis (IP configuration, virtual network adapter, firewall rules...), always check first that **every relevant piece of equipment is actually powered on**. A basic reflex, easy to forget once focused on more complex technical hypotheses — this case shows that a trivial first-level check should always come before deeper diagnosis, to avoid wasting time chasing false leads.
